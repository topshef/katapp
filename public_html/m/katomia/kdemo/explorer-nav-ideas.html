The core idea

The board today is a deal surface. But everything on it — players, accounts, assets, tokens — is an entity worth inspecting in its own right. If every tap opens a small, consistent detail surface with onward links, the game becomes a browsable graph: a mini-explorer of the accounts and assets sitting inside it, with the deal circle as just one view of that graph. That's a retention story too — you can wander, look things up, follow people between circles, even when you're not actively trading.

The navigation graph

tap CHIP → Asset card (shipped 2026-08-05: art · HashScan token · owner · remove-from-table) tap FELT/segment → Player modal (NEW — "overdue": identity + assets + reputation + games) Asset card ▸ owner → Player modal (swap in place — same overlay, new subject) Asset card ▸ token → Token view (later: holders of this token, in-game / beyond) Player modal ▸ game → another circle (deep link: jump to a game this player is also in) Player modal ▸ ⋯ → invite · message · block (context actions, some exist as tasks already)

One rule keeps it learnable: tap an asset → asset; tap empty felt in a wedge → its player. Every surface shows its subject's links to the other two entity types.

The player modal (PLAYER-MODAL1)

Header: avatar (kemoji) on player colour · name (if any) · account id(s) with 🔷/△ binding marks · "you" when self.
Assets: full scrollable list of their store (and basket?) — each row tappable through to the asset card.
Reputation & identity: published bindings (link to binding.php), XProof records, later reputation facets (MVP-REPUTE1).
History: their transactions in this game (BOARD-TXHISTORY1 feeds this), later cross-game.
Games: which other circles this player is in → tap to jump (see deep links below).
Actions: invite-to-game · message (chat @) · block (BOARD-BLOCK1) — greyed where not wired yet, per the no-phantom-controls rule.

Curation lives here (BOARD-CURATE1 fold-in)

  • The asset list in the player modal is where swipe left = hide / swipe right = restore works naturally — a scrollable list is the right home for a Tinder-style gesture (on the felt it would fight drag-to-offer).
  • Hidden = greyed out + dropped to the bottom of the list, and the chip leaves your board only (per-viewer, localStorage). Always reversible from the same list — no invisible state.
  • The board wedge shows a small "3 hidden · show" pill so hidden state is always discoverable.
  • Contrast (already shipped): removing your own asset via the asset card is global (game_removeAsset) — different verb, different scope, and the copy should keep saying so.

Deep links & the explorer angle

  • Give player / asset / token views URL forms (e.g. /m/katomia/game/<id>?player=p3, ?asset=0.0.x) so they're shareable and the back button works — the explorer becomes linkable tissue between circles, not a page you leave the game for.
  • "Also in: 🐫 t-prop · 🧵 Silk Road" on the player modal = the jump between circles. The same component on a landing page is "follow this trader".
  • Token view (later): holders of this token in the game, then beyond it (mirror query) — from there, invite a holder is the natural growth loop: the explorer finds the counterparty, the invite pulls them in.
  • Spectator mode already proves the browse-without-playing posture; the explorer gives spectators something rich to do.

Multi-device / multi-view

Joining the same game from two devices already yields two live views (it's all websockets). Worth making that a feature rather than an accident: e.g. phone as your hand (your store/basket + chat), desktop as the table. No new plumbing — mostly a preset of existing view options per device. Park as an idea until the explorer basics exist.

Open questions
