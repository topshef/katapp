2 · Kabila Plazas (Hedera) — the closest neighbour

Kabila is the strongest Hedera precedent: an NFT hub whose Plazas are token-gated community spaces. From their docs and app:

  • Entry: connect a Kabila Wallet holding tokens (NFT or FT) from a participating collection → the app automatically shows the communities those holdings unlock. No apply/approve step.
  • Live verification: "acquiring new tokens grants instant access… transferring or selling automatically revokes" — access is a live function of holdings, not a granted-once membership.
  • Tiers: a plaza can run multiple topic channels with different token thresholds.
  • Directory is public (screenshot below): names, member counts, one-line pitches — the gate is on the content, not the discovery. Plaza sizes today are modest (flagship 677 holders; typical 25–130) — useful calibration for what "community scale" means on Hedera right now.
Caveat for us: Kabila's flow is anchored on their own wallet, which lowers friction inside their ecosystem but is exactly the lock-in Katomia avoids by using WalletConnect (HashPack, Kabila wallet, Blade… all arrive through one pairing flow). Our "global position across ALL connected accounts" idea goes further than anything seen here — Kabila evaluates one wallet.

3 · ZEP.us — gamified spaces, web2 gates

  • ZEP spaces gate entry via space password or login-domain restriction (host settings), plus entry-map routing and nickname rules for anonymous guests — friendly, zero-crypto gating.
  • No native token gating found in current ZEP docs (its NFT/metaverse era features have been de-emphasised); crypto gating there would ride on custom "ZEP scripts"/apps.
  • The flip you floated (Katomia as a service embedded in a space): ZEP supports embedded mini-apps/scripts, so a Katomia market-as-widget inside someone's event space is technically plausible — but it's a distribution experiment, not launch path. Same applies to Spatial (below), which does have native token gating.

4 · Others worth one line each

  • Spatial.io — metaverse spaces with first-class token gating: restrict a space to holders of an NFT, with a minimum-quantity knob. The cleanest genre-adjacent implementation of "hold N to enter".
  • miniorange — off-the-shelf HashPack-login + Hedera NFT gating for ordinary websites: connect (public key only) → scan holdings → grant/deny pages, token→role mapping for tiers. Proof there's already a service market for exactly our lever, on our chain.
  • Collab.Land / Guild-style community gating (Discord/Telegram bots): the dominant gating UX in crypto socially — verify once, get the role. Notable because testers already understand this mental model; our authenticate-→-testers-group flow mimics it.
  • Generic token-gating SaaS (e.g. token-gating.com, Alchemy's pattern write-ups) — commodity for EVM; thin on Hedera, which is why Kabila + miniorange are the references that matter here.

5 · What this means for ENTRY-GATING1

  1. Keep discovery open, gate the room — the industry pattern and already Katomia's shape. Don't gate /welcome or the index; gate specific markets/routes when the time comes.
  2. Token spec shape: { tokenId | collection, min: N } with tiers per route/channel; copy Kabila's live-holdings semantics (re-check per session at minimum; revoke means revoke — no grandfathered sessions).
  3. Differentiator to keep: aggregate position across all connected accounts (nobody observed does multi-wallet aggregation).
  4. Cheap tier zero: a ZEP-style invite code/password gate is a legitimate tester lever that needs no chain at all — worth having in the requirement enum (invite:<code>) for day one of any throttling.
  5. Familiarity: testers arriving from Hedera NFT communities already know "connect → holdings checked → door opens" from Kabila/Collab.Land — our flow won't need explaining, which supports the low-copy minimal UX shipped today.
